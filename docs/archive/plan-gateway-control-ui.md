## 0. Locked preconditions (do first, blocks everything)

* **[C+V] Gate decision first — blocks the UI track (blocking contradiction).** All `/api/*` are unauthenticated localhost today (`router.rs:81-89`, `lib.rs` no gate, no Axum CORS layer). The draft offered "loopback-only + no CORS" while §3A had the browser reading the Control API over HTTP — impossible: the Tauri webview and the vite dev server (`vite.config.ts:9-44`, proxies only `/opencode-usage`, `/commandcode-alpha`, `/chatgpt-wham`, nothing `/api`) are both cross-origin to `127.0.0.1:11434`, so `fetch` fails with CORS off. Decision (scheduled as build step 0, before any UI wiring): Axum serves the built SPA (same-origin, no CORS needed) + add a vite `/api` proxy for preview, keeping a secret-header check against DNS rebinding. If "Tauri-command-only" is picked instead, §3A must be rewritten (browser cannot read the Control API). Read-only GETs land first under the chosen gate; mutating verbs (`PATCH`/`DELETE`/`PUT`, plus the quota-refresh `POST` in §2C) land only after it. Until then, routing edits stay read-only in UI.
* **[C+V] Accounts identity fix (migration 005) — table rebuild, not ALTER.** `accounts(id PK)` (`migrations/001_init.sql:5-10`) collides when one email links two providers. Correction to the draft's rationale: the keyring slot is NOT bare email — it is `local-token:{provider_slug}:{account_id}` (`secrets.rs:10-12`), so no keyring collision exists; the collision is purely the `accounts.id` PK (`INSERT OR IGNORE` in `db.rs:86` silently drops the second provider). SQLite has no `ALTER TABLE … PRIMARY KEY`: rebuild via `accounts_new`/`routing_policy_new` → copy → drop child first (`routing_policy` is the only FK; `usage_events`/`quota_observations` have none) → drop `accounts` → rename. `sqlx::migrate!` runs in a transaction where `PRAGMA foreign_keys=OFF` is a no-op and sqlx 0.8 enables FK enforcement — so child-first ordering is load-bearing; spell the recipe in the migration file. Then: new PK `(provider_slug, id)`; update `routing_policy` FK, `candidate_accounts` (`router.rs:239`), `default_account_for` (add missing `COALESCE(r.enabled,1)=1` to match rolling — and rewrite its test, which passes today only because `go-a` sorts before disabled `off-c` alphabetically at `router.rs:1096-1100`; new test needs a disabled account sorting FIRST), `register_account` (`db.rs:79-109`, and pin `INSERT OR IGNORE` so re-verify updates plan but never clobbers a user-edited `label`), all 9 `record_usage` call sites. Add `UPDATE accounts SET credential=NULL` (legacy `002_routing_policy.sql:1` column is only a comment-guard in `router.rs:1013-1016` today) + regression test asserting NULL. `DELETE /api/accounts/:provider/:id` runs in a transaction deleting `routing_policy` BEFORE `accounts` (FK order), retains `usage/quota` rows under tombstone, keyring clear best-effort last with explicit error.
* **[C] Retry single-layer.** `post_alpha_generate` retries internally (`BRIDGE_MAX_RETRIES: u32 = 2` compile-time const at `commandcode.rs:342`, not an env var) AND `route_chat` rolls on retryable — 3x pressure. Delete one layer for the bridge (keep caller-roll, remove inner loop except timeouts), and new adapters stay single-attempt + caller-roll.
* **[V] Error envelope — canonical shape (draft misdescribed it).** Actual wire: `openai_error` emits `{error:{message, type, code}}` with `code` = numeric HTTP status and the `proxy_dock_*` string in `type` (`router.rs:68-74`); `gateway_not_ready` nests `provider` INSIDE `error` (`router.rs:974-985`, one place only); `provider_models` 404 omits `type` entirely (`router.rs:137`). Canonical going forward: `{error:{message, type:<proxy_dock_*>, code:<numeric HTTP status>, requestId?, provider?}}` with `provider` inside `error`; fix the 404 to include `type`. Already-existing codes (not "new"): `proxy_dock_bad_model`, `proxy_dock_unknown_provider`, `proxy_dock_all_accounts_failed`, `proxy_dock_adapter_disabled`, `proxy_dock_not_configured`/`proxy_dock_adapter_pending`, `commandcode_bridge_error`, `codex_upstream_error`, `antigravity_upstream_error`, `opencode_upstream_error`. Genuinely new: `proxy_dock_no_plan` (token but unservable plan — replaces misleading `adapter_pending`). Never bare `bad_model/no_token/no_plan`.
* **[C+V] UI honesty cut first (no backend needed).** Delete `homeTotals`-from-mocks path (`Home.tsx:48-62`, `data.ts:70-85`, `TREND_POINTS`), `$3/M` savings formula (`Home.tsx:58`), unreachable `provider.accounts` branch (`ProviderPage.tsx:604-640`), `MOCK_PROVIDERS`/`consumeResetCredit`/`listProviderAccountIds` dead exports, `providersProp` seam (never passed — `App.tsx:26` renders `<Home onOpenProvider>` only; delete, don't relocate); collapse the two diverging `daily-empty` testids/copy (`Home.tsx:113,115`) into one; unify the `account-*`/`quota-*` testid scheme while extracting `quotaTone` (both `AccountBlock` and `ProviderQuotaList` use them — they collide when both render). Kill the `commandcodePlan` monthly-numbers cost presentation AND label the table's provenance (see §2D note); kill the `displayPlanFor` Go-guess (`auth.ts:127-131` returns `"Go"` for any plan-less opencode key — the one place the UI fabricates a fact; return `null`). Make Settings gateway input `readOnly` + honest TBD copy, tray checkboxes marked unimplemented (no fake controls).

## 2. Control API / persistence

Current: `GET /api/providers`, `/api/accounts(?provider=)`, `/api/usage/summary` (global totals, cost coalesced to `0.0` in `router.rs:1039-1052` — breaks NULL-means-unknown). Quota via Tauri command only, never persisted. `pricing_snapshots` has NO price columns (`001_init.sql:27-33`); `quota_observations.remaining TEXT` holds no defined serialization; `usage_events.created_at` is `datetime('now')` TEXT (`2026-09-27 12:00:00` — space-separated, NOT RFC-3339).

* **[V] 2A Usage (reads first) — timestamps are fixed, not documented.** `GET /api/usage/events?provider&account&model&since&until&limit&cursor` (`ORDER BY id DESC`, `limit=min(limit,500)`, cursor `id<`), `GET /api/usage/summary?group_by=provider|account|model|day&since&until` (SQL `GROUP BY`). Clients send RFC-3339 bounds but storage is `datetime('now')` TEXT, so lexicographic comparison mis-filters same-day ranges (`' ' < 'T'`) and non-UTC offsets — normalize bounds server-side to UTC `YYYY-MM-DD HH:MM:SS` before binding (same for `?since` in 2C/2F). New tables store new timestamps as UTC `YYYY-MM-DD HH:MM:SS`; convert to RFC-3339 on read. Identity is the `(provider_slug, id)` pair post-§0: `group_by=account` groups by the pair (one email on two providers must NOT merge), and `?account=` filters require `?provider=` alongside (account ids are emails containing `@` — URL-encode `:id` path params). Cost: `estimated_cost` column already exists (`001_init.sql:23`) but all 9 `record_usage` sites bind NULL (`router.rs:548-561`) — keep the column, fix the `COALESCE(...,0.0)` masking so NULL means unknown, add `estimated:boolean`. Token columns stay prompt/completion (+total); reasoning/cache deferred. Migration 005 creates `idx_usage_q(provider_slug,account_id,model,created_at,id)` (it belongs to 005 — listed here because it serves this query).
* **2B Routing + accounts (reads, then writes post-gate).** `GET /api/routing/accounts?provider=` returns canonical ordered candidates `{accountId,label,priority,enabled,isDefault,plan,hasToken}` using the SAME `ORDER BY COALESCE(r.priority,a.priority,1), a.id` as `candidate_accounts` (`router.rs:239`) — lower number first, ties break on `a.id` (email sort); document both since `isDefault` depends on them. `PATCH /api/accounts/:provider/:id {label?,priority?,enabled?}` maps `label → accounts.label`, `priority/enabled → routing_policy` (with the `accounts.priority` fallback in the `COALESCE`); label ≤64 chars, priority int 0..100, enabled bool; unknown provider/account → 404, bad value → 422. `DELETE /api/accounts/:provider/:id` per §0 rule (child-first, transactional). Canonical ordering query shared by gateway + API (single function).
* **[V] 2C Quota history + refresh endpoint (missing from the draft).** Every quota refresh inserts `quota_observations(provider_slug,account_id,remaining,reset_at,observed_at)` where `remaining` = canonical JSON of `Vec<QuotaRow>`; `reset_at` = UTC `YYYY-MM-DD HH:MM:SS` (NOT RFC-3339 — keeps one format per table; note the draft cited `quota.rs:84-89 parse_reset` as rationale, but that function returns epoch millis, not RFC-3339). Best-effort, never fails refresh. `GET /api/accounts/:provider/:id/quota/history?since&limit` for sparklines (bounds normalized per 2A); UI shows last-known on failure. No new quota index — `idx_quota_observations_account(account_id,observed_at)` from `002` already covers it (the draft's `idx_quota_q` was identical; dropped). Missing surface the UI needs: `POST /api/accounts/:provider/:id/quota/refresh` fronting the Tauri `refresh_quota` command (`quota.rs:901-911`) — a POST, so it sits BEHIND the §0 gate with the other mutating verbs, not in the read-first batch.
* **[V] 2D Pricing (manual only).** `PUT /api/pricing/:provider/:model {prompt_per_1k, completion_per_1k, source}` → `pricing_snapshots ADD COLUMN price_json TEXT NOT NULL DEFAULT '{}' CHECK(json_valid(price_json))` + `UNIQUE(provider_slug, model)` (migration 005) with upsert semantics: PUT writes a new snapshot row and latest-wins on read (append history, don't overwrite). `record_usage` fills `estimated_cost` when a snapshot exists else NULL. No scraping; Studio reconciliation out of scope. Provenance note: the `commandcodePlan` pool table (`auth.ts:1616-1633`, mirrored in Rust `quota.rs`) maps plan→credit-pool for the Credits quota bar ONLY (same CLI-mirrored source as Rust) — it is never a price and never feeds cost; the honesty cut removes its cost presentation and labels the source.
* **2E Model cache API.** `GET /api/models?provider=` serves cache `{nativeId,endpoints[],contextLength|null,updated_at,stale}` (`endpoints` JSON array of `chat|responses|messages`; `updated_at` UTC TEXT; `stale` = older than TTL 24h); refresh path shared with 1A. Migration 005 creates `idx_cache_slug(provider_slug)`.
* **2F Events log.** New `gateway_events(id PK, created_at UTC TEXT, provider_slug, account_id, model, route, outcome, status, latency_ms, error_snippet TEXT truncated, no secrets)` (migration 006). `GET /api/events?provider&account&since&limit` (cap 500, bounds normalized per 2A). Prune in background task (1/min, keep newest 10k rows within 30d — newest-wins). Migration 006 creates `idx_events_q(provider_slug,created_at)`.
* Migrations: 005 (accounts/routing rebuild for PK + credential NULL + pricing price_json + UNIQUE + model_cache endpoints/updated_at + `idx_usage_q` + `idx_cache_slug`), 006 (gateway_events + `idx_events_q`). 001–004 untouched (sqlx checksums). `pool()` runs `migrate!`; seed unchanged.
* Acceptance: fresh + existing-DB migration tests, ordering/validation/cap tests, NULL-cost vs estimated tests, keyring/DB consistency tests.
